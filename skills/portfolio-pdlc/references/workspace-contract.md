# Portfolio Workspace Contract

The single source of truth for what makes a folder a portfolio workspace. Every
`portfolio-pdlc-*` skill and script reads/writes against this contract. Change it here first;
the templates in `../templates/` instantiate it.

## Layout

```
<portfolio-workspace>/
  AGENTS.md            # thin router: points agents at the portfolio-pdlc skills + operating loop
  PORTFOLIO.md         # charter — anchor, not plan; locked sections; readable in <5 minutes
  pdlc.md              # definition of workflow (stages, confidence contract, policies) + board-config block
  topology.md          # teams/groups/platforms, dependency notes, candidate topology options
  board.md             # GENERATED by scripts/portfolio_board.py — never hand-edit
  flow-log.csv         # GENERATED append-only stage-transition log — never hand-edit (backfill via wire skill only)
  initiatives/
    <slug>/
      initiative.md    # the card — frontmatter is the machine state, body is the human story
      ...              # optional: canvas.md, evidence files, anything the initiative accumulates
  improvements/
    <slug>/
      improvement.md   # same schema; type improvement-process | improvement-topology
  reviews/
    YYYY-MM-DD-<intent>.md   # assessment briefs, decision briefs, retro notes
    loop-log.md              # one line per operating-loop cycle
  learnings/
    <slug>.md          # one durable learning per file (format below)
```

Slugs: kebab-case, outcome-flavored where possible (`churn-save-desk-reduction`, not
`project-phoenix`). The folder name is the slug and never changes; retitle in frontmatter.

## Card frontmatter schema (`initiative.md` / `improvement.md`)

Keep it parser-friendly: flat keys, lists of scalar strings, no nested maps. The board
script parses this subset deterministically — exotic YAML will be flagged, not guessed at.

```yaml
---
title: Studio owners renew without a save-desk call     # outcome-oriented name
type: product          # product | platform | transformation | improvement-process | improvement-topology
tier: 1                # 1 = managed on the portfolio board | 2 = awareness lane
stage: discovery       # explore | discovery | plan-commit | execute | rollout | bau | done | frozen
stage_entered: 2026-07-28
owner: Dana
sponsor: Mary
outcome_hypothesis: "If studios can self-serve plan changes, voluntary churn drops"
leading_indicators:
  - "self-serve plan-change completion → 60% (current: n/a)"
  - "save-desk call volume → -30% (current: 210/mo baseline)"
risk_level: high       # low | medium | high — dominant open DVF risk
derisking_approach: discovery   # just-do-it | ship-and-measure | discovery | seek-alpha
orientation: outcome   # outcome | activity | mixed — ASSESSED by portfolio-pdlc-assess, not aspirational
portfolio_score: 7     # size + strategic + collaboration, 1–3 each; 3–4 shouldn't be Tier-1, 7–9 should
dependencies: [billing-platform, data-team]
next_decision: "2026-08-25 — invest in full discovery? (sponsor)"
---
```

Field rules:

- `stage` values come from the workspace's `pdlc.md` board-config; the list above is the
  framework default. `done` means "left the portfolio flow"; `frozen` is an explicit,
  dated leadership decision, not a euphemism for stalled.
- `stage_entered` updates on every transition — it's what makes item age computable.
- `orientation` is written by the assess skill after applying the input→impact ladder to the
  card. Nobody gets to self-declare `outcome`.
- `next_decision` is free text but starts with a `YYYY-MM-DD` date when a date exists —
  the board script reads that prefix to flag overdue decisions.
- Omitted fields are flagged by the board script, not defaulted silently. A new Explore card
  may legitimately lack `outcome_hypothesis` for a cycle or two; the flag is the reminder.

## Card body sections (recommended, not parsed)

`## Problem / Opportunity` · `## Outcome hypothesis & indicators` (the detail behind the
frontmatter) · `## Riskiest assumptions` (each tagged **evidence** or **opinion**) ·
`## Derisking plan` · `## Decision log` (dated, named humans — stage-boundary transitions
require an entry here) · `## Evidence log` (dated findings; what changed our confidence).

Improvement cards add: `## Benefit hypothesis` · `## Success / kill criteria` ·
`## Discovery approach` (probe, pilot scope, or simulation scenario).

## Generated files

- `board.md` — full projection: per-stage tables (Tier-1 by age, improvements lane,
  Tier-2 awareness list), WIP vs limits, risk-balance split, orientation counts, flags.
  Regenerate rather than edit; edits are lost by design.
- `flow-log.csv` — `date,slug,from_stage,to_stage` rows appended by the board script when a
  card's `stage` differs from its last logged stage (transition date = the card's
  `stage_entered`). Feeds cycle time, throughput, and the simulator. Append-only.

## `pdlc.md` board-config block

Machine-readable island inside the human document (the script falls back to defaults if
absent):

```
<!-- board-config
stages: explore, discovery, plan-commit, execute, rollout, bau
optional_stages: discovery, rollout
wip_limits: plan-commit=3, execute=4
aging_thresholds: explore=30, discovery=45, plan-commit=30, execute=120, rollout=45
decision_boundaries: plan-commit, execute
-->
```

`decision_boundaries` lists stages a card may only ENTER with a dated human decision in its
Decision log.

## Learning files (`learnings/<slug>.md`)

One learning per file — never batch. Frontmatter: `date`, `category`
(`process | topology | card-quality | flow | watermelon | tooling`), `initiative` (slug or
`portfolio`), `severity` (`note | significant | systemic`). Body: what happened → what we
now believe → what the next cycle does differently. If it implies a change to the operating
model, ALSO capture an improvement card; the learning records the evidence, the improvement
card carries the bet.

## Invariants

1. The board and flow log are projections; card frontmatter is the state. Disagreement
   between them is a bug in the cycle, not a matter of opinion.
2. Stage labels are claims until verified against evidence (assess skill).
3. Decision-boundary transitions without a Decision-log entry are contract violations —
   the board script flags them (it checks for a `## Decision log` dated entry heuristically;
   the assess skill checks it properly).
4. Nothing in this contract requires a specific agent harness, tracker, or OS.
